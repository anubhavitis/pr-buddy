pr-buddy

GitHub sorts your files alphabetically.
pr-buddy sorts them so they make sense.

A Chrome overlay on the Files tab. A local model reorders the tree and the stacked diffs, and writes a line on what each file is doing here. You still write every comment.

What it fixes

  • Alphabetical is not a reading order.

    The type that explains the change sits three folders below the code that uses it, so you scroll up and down rebuilding the shape of it in your head. Position matters more than it looks: on IntelliJ IDEA, Bagirov et al. found reviewers leave more comments on files shown higher up, and that ordering by diff beat alphabetical at putting the risky files where someone would actually look. Reviewers already work around this, commenting out of alphabetical order on 44.6% of pull requests in a study of 23,241 of them. pr-buddy hands you that order up front.

  • You open the diff not knowing what any file is for.

    Every file is a wall of green and red you have to classify yourself, and that cost lands hardest on bugs spread across several files. Baum, Schneider and Bacchelli ran 50 mostly professional developers through seeded reviews: the ones with more working memory to spare caught more delocalized defects, the kind you only see by holding several files at once. pr-buddy writes a line or two per file and a summary per group, so that attention goes to the code instead of to orientation. Straight version: the same study could not reliably show that reordering alone improves defect find rate. This buys you ergonomics, not a proven win.

Install: two pieces

  • 01

    The host binary

    Connects your machine's AI backend to the browser. Run it and leave it running on 127.0.0.1:17342. If macOS blocks it: right-click, then Open.

    Download host Mac M-series
  • 02

    The Chrome extension

    Unzip it, then Chrome, chrome://extensions, Developer mode, Load unpacked. Open a PR Files tab and click the pr-buddy pill.

    Download extension .zip

Install the host first. The extension needs something to talk to, and if the host is not running the overlay just says host offline — start pr-buddy-host. Start the binary and click again. You need Chrome, an Apple Silicon Mac, and one of claude, grok, or mlx already installed. No Go, no npm.

How it works

Two installs. The extension rewrites the GitHub page; the host runs your model. They talk over 127.0.0.1:17342, a port on your own laptop.

The extension sends the file paths, the PR title and description, and the head SHA. Your diff is never sent. pr-buddy never checks out, builds, or runs the branch. claude and grok reach their vendor API with that same metadata; mlx stays fully offline.
