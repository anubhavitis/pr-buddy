A Chrome overlay on the Files tab. A local model reorders the tree and writes a line on what each file is doing here. You still write every comment.

    Why the order matters

    • 44.6% of pull requests get commented out of alphabetical order. Reviewers already fight the default, and files shown higher up get more comments than the ones below. 23,241 PRs · Bagirov et al.
    • 50 devs in seeded reviews: the ones with more working memory to spare caught more bugs spread across several files, the kind you only see by holding a few files at once. Baum, Schneider and Bacchelli

    Straight version: that second study could not reliably show reordering alone improves defect find rate. This buys you ergonomics, not a proven win.

    Install: two pieces

    • 01

      The host binary

      Connects your AI backend to the browser. Leave it running on 127.0.0.1:17342. If macOS blocks it: right-click, then Open.

      Download host Mac M-series
    • 02

      The Chrome extension

      Unzip, then chrome://extensions → Developer mode → Load unpacked. Open a PR Files tab and click the pr-buddy pill.

      Download extension .zip

    Host first: without it the overlay just says host offline — start pr-buddy-host. Needs Chrome, an Apple Silicon Mac, and one of claude, grok or mlx. No Go, no npm.

    How it works

    Your diff is never sent. Only paths, title, description and SHA. pr-buddy never checks out, builds, or runs the branch. claude and grok send that metadata to their vendor API; mlx stays fully offline.
